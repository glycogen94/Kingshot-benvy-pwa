# Kingshot PWA Prototype

A WebGPU-powered browser prototype for the mobile defense game **Kingshot**. The project mirrors the feel of the original SLG release from Century Games while running entirely in WebAssembly with an installable PWA shell. Gameplay, rendering, and simulation run inside Bevy; the DOM thread handles shell concerns and input forwarding so we can match touch-first expectations on phones and tablets.

## Current Highlights
- Tap-to-aim combat loop with hero, enemy wave, and projectile scaffolding.
- Pointer/gesture bridge that normalises touch, pen, and mouse input across worker and main-thread execution.
- Worker-hosted WebGPU renderer with automatic fallback when OffscreenCanvas or Workers are unavailable.
- Installable PWA experience (manifest + service worker) and Vite-powered dev/build pipeline.
- Living design notes in [`docs/kingshot-plan.md`](docs/kingshot-plan.md) outlining upcoming gameplay, UX, and polish milestones.

## Prerequisites
- **Rust 1.85+** with the `wasm32-unknown-unknown` target installed.
- **wasm-bindgen-cli 0.2.104** (`cargo install wasm-bindgen-cli@0.2.104`).
- **Node.js 18+** and npm for the Vite toolchain.
- A WebGPU-capable browser (Chromium 121+, Safari TP, or Firefox Nightly with the WebGPU flag).

## Development Workflow
```sh
# Install JS dependencies once
npm install

# Launch the dev server (builds wasm + starts Vite on :5173)
npm run dev

# Production build (emits dist/ with wasm + JS bundles)
npm run build

# Preview the production build locally
npm run preview
```

The dev/build scripts regenerate `web/pkg/` via `wasm-bindgen` before starting Vite, so Rust changes are reflected automatically.

### Worker toggle
The renderer defaults to the main thread. Enable the worker path with `?worker=1` in the URL or set `window.__kingshot_enableWorker = true` before `main.js` runs. Both paths instantiate the same `KingshotApp` export coming from the wasm module.

## Controls
- **Tap / Click**: aim at the touched position; the hero fires when a pointer sequence begins.
- **Drag**: continuously updates the aim reticle while the pointer is down.
- **Release / Cancel**: hides the reticle until the next pointer interaction.

These gestures are emitted to Bevy as `PointerInputEvent` instances (see `src/input.rs`). Future work will map additional gestures (flicks, multi-touch, pinch zoom) to abilities and camera moves.

## Project Layout
```
├─ Cargo.toml            # Rust crate metadata (cdylib for wasm)
├─ src/
│  ├─ lib.rs             # wasm entry, window plumbing, plugin registration
│  ├─ core.rs            # app states, session tracking, shared config
│  ├─ input.rs           # pointer payload decoding + Bevy events
│  ├─ game/              # loading/menu/gameplay plugins and systems
│  ├─ logging.rs         # tracing setup for wasm/native builds
│  └─ p2p.rs             # optional rollback networking (behind `p2p` feature)
├─ web/
│  ├─ index.html         # canvas shell
│  ├─ main.js            # main-thread bootstrap + input bridge
│  ├─ worker.js          # dedicated worker runtime for Bevy
│  ├─ manifest.webmanifest / public/  # PWA metadata + assets
│  └─ pkg/               # generated by wasm-bindgen (ignored in git)
├─ docs/
│  └─ kingshot-plan.md   # design + engineering plan (kept up to date per milestone)
└─ README.md             # you are here
```

## Roadmap Snapshot
The short-term backlog lives in `docs/kingshot-plan.md`. Near-term goals include:
1. Richer gesture vocabulary (swipes for abilities, pinch zoom, multitouch camera control).
2. Expanded wave controller with spawn pacing, enemy variety, and score feedback.
3. HUD overlays for health, cooldowns, and combo tracking.
4. Audio layering + haptic feedback bridge for mobile devices.

Contributions, feedback, and playtest notes are welcome—open an issue or extend the plan doc with findings.
